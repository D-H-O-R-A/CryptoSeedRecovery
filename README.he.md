# 🛡️ cryptoseed

🌍 **Select Language / Selecione o Idioma:**
[Português](./README.md) | [English](./README.en.md) | [Español](./README.es.md) | [Français](./README.fr.md) | [Italiano](./README.it.md) | [Türkçe](./README.tr.md) | [Русский](./README.ru.md) | [简体中文](./README.zh.md) | [日本語](./README.ja.md) | [한국어](./README.ko.md) | [עברית](./README.he.md)


**cryptoseed** היא ספרייה ברמת ארגונית, קלת משקל ובעלת ביצועים גבוהים, שפותחה ב-**JavaScript טהור** (Node.js) ומיועדת לאבחון, אימות ושחזור של ביטויי מפתח מנמוניים קריפטוגרפיים (*seed phrases*) שאבדו, התבלבלו או הוקלדו עם שגיאות כתיב.

הספרייה פותחה תחת מערכת האבטחה והתשתית של **b2 wallet** ([better2better](https://better2better.net), בהובלת [diegooris](https://diegohorantunes.web.app/)), והיא תוכננה לספק למפתחים ולאנליסטים של אבטחה חוסן מרבי, מהירות חיפוש גבוהה במיוחד ודיוק היסטורי כירורגי בגזירת כתובות ב-**39 רשתות בלוקצ'יין ואקו-سیסטמים שונים**. כל זאת תוך עבודה אוטונומית של 100%, ללא תלות בקומפילציה מקומית של C/C++ או בחבילות חיצוניות שעלולות לפגוע בניידות של ה-build.

## 📅 וריאציות של BIP נתמכות וציר זמן היסטורי

כדי לשחזר כספים בדיוק, לא מספיק רק לדעת את המילים; עליך להבין את המפרט הטכני ואת השנה שבה נוצר הארנק. **cryptoseed** מיישמת ומכבדת בקפידה את הסטנדרטים ההיסטוריים (BIPs).

### 🔍 טבלת תקני BIP מיושמים ומתואמים

| BIP | שם התקן | יישום ותמיכה ב-**cryptoseed** |
| :---: | :--- | :--- |
| **BIP-32** | *Hierarchical Deterministic Wallets* | **תמיכה מלאה.** הבסיס של עץ הגזירה של HD. מאפשר למנוע לגזור אינסוף נתיבים של מפתחות ציבוריים/פרטיים (`xprv`/`xpub`) מסיד מאסטר יחיד באמצעות מתמטיקה טהורה של עקומות אליפטיות דרך מנוע המפתחות שלנו. |
| **BIP-39** | *Mnemonic Code* | **תמיכה מלאה.** הסטנדרט הנפוץ בתעשייה. תומך בביטויים של **12, 15, 18, 21 או 24 מילים** עם אימות בדיקת סכום (*checksum*) משולב של 4 עד 8 סיביות ומילונים ב-**10 שפות שונות**. |
| **BIP-43** | *Purpose Field* | **תמיכה מלאה.** מכבד את המבנה שהציג את שדה הייעוד (`m / purpose'`) בראש עץ הנתיבים, ומבטיח שהמנוע מנתב נכון לארנקים רב-תכליתיים. |
| **BIP-44** | *Multi-Account* | **תמיכה מלאה.** הסטנדרט הנפוץ ביותר לנתיבי גזירה בתעשייה: `m/44'/coin_type'/account'/change/address_index`. בשימוש כברירת מחדל עבור Bitcoin Legacy, Ethereum, EVM, Solana Legacy, TRON, Cardano Legacy וכד'. |
| **BIP-45** | *Multisig HD* | **התאמת נתיב.** משמש לארנקי ריבוי חתימות בנתיבי ייעוד `m/45'`. אם אתה משחזר סיד אינדיבידואלי שהוא חלק מהגדרת multisig של BIP-45, המנוע גוזר את המפתחות הפרטיים הבודדים מנתיב זה כרגיל. |
| **BIP-47** | *Payment Codes* | **תאימות סיד.** קודי תשלום ניתנים לשימוש חוזר ופרטיים (כמו ארנקי Samourai). הגיבוי של ארנקים המשתמשים ב-BIP-47 הוא סיד BIP-39 סטנדרטי של 12 או 24 מילים. **cryptoseed** משחזר את סיד המאסטר הזה בצורה מושלמת. |
| **BIP-48** | *Multisig Structure* | **תאימות.** מבנה multisig מתקדם המבוסס על BIP-43 באמצעות הנתיב `m/48'/coin_type'/...`. תואם לשחזור סיד המאסטר החותם על עסקאות ריבוי חתימות אלו. |
| **BIP-49** | *Nested SegWit* | **תמיכה מלאה.** כתובות מעבר של ביטקוין המתחילות בתו `3` (פורמט P2SH-P2WPKH), הנגזרות תחת הנתיב הרשמי `m/49'/0'/0'/0/index`. |
| **BIP-84** | *Native SegWit* | **תמיכה מלאה.** כתובות ביטקוין מודרניות ובעלות ביצועים גבוהים המתחילות ב-`bc1q` ולייטקוין המתחילות ב-`ltc1` (פורמט Bech32), הנגזרות תחת הנתיב `m/84'/0'/0'/0/index` (ועבור לייטקוין `m/84'/2'/...`). |
| **BIP-85** | *Child Seeds* | **תאימות מושגית.** מאפשר לסיד מאסטר BIP-39 לייצר סידי בת מאובטחים חדשים (של 12 או 24 מילים) עבור ארנקים אחרים תחת נתיבים כמו `m/85'/...`. אם הסיד האבוד שלך הוא סיד בת שנגזר על ידי BIP-85, המנוע ישחזר אותו כמו כל סיד BIP-39 רגיל. |
| **BIP-86** | *Taproot* | **תמיכה מלאה.** כתובות ביטקוין מהדור הבא (חתימות Schnorr/Taproot) המתחילות ב-`bc1p` (פורמט Bech32m), הנגזרות תחת נתיב הסטנדרט `m/86'/0'/0'/0/index`. |

## ⚡ מדוע נוצר cryptoseed?

כאשר הייתי צריך לשחזר ארנקים עבור לקוחות וחברים של אקו-סיסטם **b2 wallet** / [better2better](https://better2better.net), הבנתי שהכלים הקיימים היו מורכבים מדי (הדרשו קומפילציות מקומיות של C++ ששברו את Node) או שלא הבינו את המעבר ההיסטורי של רשתות הבלוקצ'יין. יצרתי את הספרייה הזו כדי להציע את הפתרונות הבאים:

1.  **אפס תלות מקומית (Pure JS):** עובד ללא כאבי ראש ב-Windows, Linux או macOS. מצוין להידור קבצי הרצה ניידים באמצעות `pkg`.
2.  **טכנולוגיית "חיתוך אותיות" (Prefix Fallback):** כתבתי אלגוריתם שאם תקליד מילה שגויה כמו `engino`, הוא יחתוך את המילה תו אחר תו (`e-n-g-i-n-o` -> `e-n-g-i-n` -> `engine`) כדי לזהות אוטומטית את המילה הסבירה ביותר במילון הרשמי.
3.  **טיפול חכם במילים חסרות:** אם האלגוריתם מוצא מילה לא ידועה ללא התאמת תחילית במילון, הוא ממיר אותה אוטומטית לתו כללי (*wildcard* - `*`) כדי לבדוק את כל אפשרויות המילון אחת אחת בצורה אוטומטית.
4.  **גיזום ענפים מוקדם (Early Branch Pruning):** פיתחתי את מנוע החיפוש עם גיזום מוקדם המבוסס על אילוצים (מילים חובה ומילים לא נכללות - NOK), מה שמונע מהמעבד לחשב מיליארדי פרמוטציות חסרות תועלת.
5.  **מעקף בדיקת סכום מובנה (Checksum Bypass):** מכיוון שסידי BIP-39 מכילים בדיקות סכום, הקוד פוסל **99.6%** מכל השילובים שנוצרו עוד לפני שהוא מנסה לעשות מתמטיקה כבדה של עקומות אליפטיות, ובכך חוסך זמן מעבד פי 1000.

## 🛠️ תכונות שחזור והנדסת חיפוש

פותח במקור בשנת **2023** ככלי בלעדי עבור האקו-סיסטם **b2 wallet** ([better2better](https://better2better.net)), **cryptoseed** הפך לקוד פתוח כדי לספק תשתית שחזור עדיפה מבחינה מדעית על פתרונות השוק הנפוצים. למנוע החיפוש יש את היכולות והיתרונות הבאים:

### 🎯 סימון מצבים לפי מילה
בניגוד לסקריפטי שחזור פשוטים, האשף האינטראקטיבי מאפשר לך להגדיר את רמת האמון של כל מילה בסיד בנפרד באמצעות שלושה סיווגים סמנטיים:
* **✔️**: המילה ומיקומה המדויק בסיד מאושרים. המנוע נועל מילה זו וממקד את משאבי העיבוד אך ורק בשאר המיקומים.
* **🔀**: המילה ידועה ושייכת לקבוצה, אך מיקומה אינו נכון או אינו ודאי. המנוע שוקל מילה זו באופן דינמי עבור פרמוטציות בטוחות רק במיקומים הפנויים הזמינים, ובכך מונע בדיקות כפולות.
* **🎲**: המילה אבודה לחלוטין או שאינה קריאה. המנוע בודק באופן אוטומטי ומקיף את כל האפשרויות ממילון הפורמט המתאים.

### 📊 עיבוד מקדים והערכת היתכנות
לפני הוצאת אנרגיית עיבוד כבדה, המנוע מנתח את הסיד ואת האילוצים שסופקו כדי להציג פאנל מתמטי מפורט:
* **מרחב חיפוש גולמי**: מציג את הסך המתמטי המדויק של השילובים התיאורטיים שיש לקונפיגורציה הנוכחית.
* **גיזום עץ (סכום ביקורת ומסננים)**: מדווח כמה שילובים נותרו לאחר החלת מסננים לוגיים מהירים (כמו סכומי ביקורת או הגבלות על מילות NOK), מה שמפחית באופן דרסטי את נפח גזירות המפתחות הכבדות.
* **תחזיות זמן סריקה**: משווה בזמן אמת את הערכת זמן הסריקה בעת שימוש בחיבורים בעלי השהיה ממוצעת (APIs ציבוריים) לעומת חיבורים מקומיים בעלי ביצועים גבוהים (צומת RPC מקומי).
* **אזהרת אי-היתכנות**: המנוע מזהיר את המשתמש באופן שקוף אם המורכבות המוגדרת דורשת כוח של מחשב-על, ובכך מונע נעילה מיותרת של חומרת המשתמש.

### 🌐 מנועי אימות ופורמטים מרובים
האקו-סיסטם תומך במבנים קריפטוגרפיים שונים עם כללי אימות ספציפיים לכל פורמט:
* **מנוע BIP-39**: תומך בסידים של **12, 15, 18, 21 ו-24 מילים**, ומחיל בדיקת תקינות (*checksum*) משולבת כדי לפסול **99.6%** מההשערות השגויות לפני הגזירה.
* **מנוע Electrum**: אימות וגזירה המבוססים על הכללים הייחודיים של סידי Electrum (Legacy ו-Modern).
* **מנוע Electron Cash**: התאמה מדויקת של לוגיקת הגזירה ואימות סכומי הביקורת של האקו-סיסטם של Bitcoin Cash.
* **מצב ללא אימות (Brute Force)**: מנוע גזירה גולמי ללא בדיקת checksum; אידיאלי עבור פורמטים ישנים קנייניים או סידים מותאמים אישית שאינם סטנדרטיים, ומבטיח טווח חיפוש מקסימלי.

### 🧩 פתרון מקרים משולבים מורכבים
המנוע פותר בעיות מורכבות גבוהה בהרצה אחת, כולל:
* מילה אחת או יותר שאבדו לחלוטין במיקומים ידועים או לא ידועים.
* מילים ידועות שסדרן התבלבל.
* תרחישים מעורבים (למשל: כאשר חסרות מילים ובמקביל המילים הידועות אינן במקומן הנכון).
* בחירת פרופיל חיפוש: **מהירות מקסימלית** (תוך שימוש בסכומי ביקורת ומגבלות) או **טווח מקסימלי** (כוח גס מתמטי רחב).

## 🛡️ כיצד להשתמש בקוד שלך (JavaScript API)

הספרייה מספקת ייצוא נקי ומובנה היטב לשילוב מיידי של לוגיקת האבטחה של **b2 wallet** באפליקציה שלך:

```javascript
const { wordlists, searchEngine, addressDeriver, typo } = require('cryptoseed');

// 1. תיקון שגיאת הקלדה באמצעות "חיתוך אותיות"
const dictionary = wordlists.bip39.he || wordlists.bip39.en;
const wordWithError = "*";
const suggestions = typo.getPrefixSuggestions(wordWithError, dictionary);
console.log("המילה שנגזרה:", suggestions); // מחזיר [ 'engine' ]

// 2. גזירת כתובת ציבורית אמיתית עבור MetaMask (EVM)
const seed = "cabin engine harvest fiction witness walnut ladder tumble insect fox notable spoon";
const ethAddress = addressDeriver.deriveAddress(seed, 'metamask', 'ETH', 0);
console.log("כתובת Ethereum:", ethAddress);

// 3. גזירת כתובת מותאמת אישית באמצעות קריפטוגרפיה של B2 Wallet
const b2Address = addressDeriver.deriveAddress(seed, 'b2wallet', 'BTC', 0);
console.log("כתובת Bitcoin ב-B2 Wallet:", b2Address);
```

## 🛠️ ביצועים: צומת RPC מקומי לעומת API ציבורי

בסוף כל חיפוש, **cryptoseed** שומר דוח שחזור מפורט בדיסק שלך (`resultado_recuperacao_[timestamp].txt`) ומספק הערכה אמיתית של מהירות השאילתה כדי לבדוק אם לסידים שנמצאו יש יתרה ברשת:

*   **שאילתה באמצעות ממשקי API ציבוריים (50 מילישנייה לבקשה):** שימושי רק אם יש לך מעט מאוד סידים מועמדים ($<100$). סובל מהשהיית אינטרנט וחסימת מגבלות בקשות.
*   **שאילתה באמצעות צומת RPC מקומי (0.1 מילישנייה לבקשה):** הדרך האידיאלית לחיפושים חזקים ($>1000$ סידים). מפחית את זמן הסריקה הכולל עד **פי 500** על ידי הרצה מקומית על המחשב שלך.

**cryptoseed** — это библиотека корпоративного класса, легкая и высокопроизводительная, разработанная на **чистом JavaScript** (Node.js) и предназначенная для диагностики, валидации и восстановления криптографических мнемонических фраз (*seed phrases*), которые были утеряны, перепутаны или введены с орфографическими ошибками.

Разработанная в рамках экосистемы безопасности и инфраструктуры **b2 wallet** ([better2better](https://better2better.net) под руководством [diegooris](https://diegohorantunes.web.app/)), библиотека спроектирована так, чтобы предоставить разработчикам и аналитикам безопасности максимальную надежность, сверхвысокую скорость поиска и хирургическую историческую точность при выводе адресов в **39 различных блокчейнах и экосистемах**. Все это работает на 100% автономно, без каких-либо зависимостей от компиляции нативного C/C++ или внешних пакетов, которые могли бы поставить под угрозу переносимость сборки.

## 📅 Поддерживаемые стандарты BIP и историческая хронология

Чтобы точно восстановить средства, недостаточно просто знать слова; необходимо понимать технические спецификации и год, когда был создан кошелек. **cryptoseed** строго реализует и соблюдает исторические стандарты (BIP).

### 🔍 Таблица реализованных и согласованных стандартов BIP

| BIP | Название | Реализация и поддержка в **cryptoseed** |
| :---: | :--- | :--- |
| **BIP-32** | *Hierarchical Deterministic Wallets* | **Полная поддержка.** Основа дерева деривации HD. Позволяет движку получать бесконечные пути открытых/закрытых ключей (`xprv`/`xpub`) из одной мастер-фразы, используя чистую математику эллиптических кривых с помощью нашего движка ключей. |
| **BIP-39** | *Mnemonic Code* | **Полная поддержка.** Отраслевой стандарт. Поддерживает фразы из **12, 15, 18, 21 или 24 слов** со встроенной 4–8-битной проверкой контрольной суммы (*checksum*) и словарями на **10 различных языках**. |
| **BIP-43** | *Purpose Field* | **Полная поддержка.** Соответствует структуре, которая ввела поле назначения (`m / purpose'`) на верхнем уровне дерева путей, обеспечивая правильную маршрутизацию к многоцелевым кошелькам. |
| **BIP-44** | *Multi-Account* | **Полная поддержка.** Самый распространенный стандарт пути деривации в индустрии: `m/44'/coin_type'/account'/change/address_index`. Используется по умолчанию для Bitcoin Legacy, Ethereum, EVM, Solana Legacy, TRON, Cardano Legacy и т. д. |
| **BIP-45** | *Multisig HD* | **Сопоставление путей.** Используется для мультисиг-кошельков на путях назначения `m/45'`. Если вы восстанавливаете индивидуальную фразу, которая является частью мультисиг-настройки BIP-45, движок обычно выводит отдельные закрытые ключи из этого пути. |
| **BIP-47** | *Payment Codes* | **Совместимость фраз.** Многоразовые и приватные платежные коды (такие как кошельки Samourai). Резервная копия кошельков, использующих BIP-47, представляет собой стандартную фразу BIP-39 из 12 или 24 слов. **cryptoseed** отлично восстанавливает эту мастер-сид фразу. |
| **BIP-48** | *Multisig Structure* | **Совместимость.** Продвинутая мультисиг-структура на основе BIP-43 с использованием пути `m/48'/coin_type'/...`. Совместим для восстановления мастер-фразы, подписывающей эти мультисиг-транзакции. |
| **BIP-49** | *Nested SegWit* | **Полная поддержка.** Переходные адреса Биткоина, начинающиеся с символа `3` (формат P2SH-P2WPKH), полученные по официальному пути `m/49'/0'/0'/0/index`. |
| **BIP-84** | *Native SegWit* | **Полная поддержка.** Современные высокопроизводительные адреса Биткоина, начинающиеся с `bc1q`, и Лайткоина, начинающиеся с `ltc1` (формат Bech32), выведенные по путям `m/84'/0'/0'/0/index` (и `m/84'/2'/...` для LTC). |
| **BIP-85** | *Child Seeds* | **Концептуальная совместимость.** Позволяет мастер-сид фразе BIP-39 генерировать новые безопасные под-фразы (из 12 или 24 слов) для других кошельков по таким путям, как `m/85'/...`. Если ваша утерянная фраза была дочерней фразой, полученной с помощью BIP-85, движок восстановит ее как любую обычную фразу BIP-39. |
| **BIP-86** | *Taproot* | **Полная поддержка.** Адреса Биткоина последнего поколения (Schnorr/Taproot), начинающиеся с `bc1p` (Bech32m), полученные по стандартному пути `m/86'/0'/0'/0/index`. |

## ⚡ Зачем был создан cryptoseed?

Когда мне потребовалось восстановить кошельки для клиентов и друзей экосистемы **b2 wallet** / [better2better](https://better2better.net), я понял, что существующие инструменты либо слишком сложны (требуют компиляции нативного C++, которая ломает Node), либо не понимают исторический переход блокчейнов. Я создал эту библиотеку, чтобы предложить следующие решения:

1.  **Ноль нативных зависимостей (чистый JS):** Работает без головной боли на Windows, Linux или macOS. Отлично подходит для компиляции переносимых исполняемых файлов с помощью `pkg`.
2.  **Технология «нарезки букв» (Prefix Fallback):** Я написал алгоритм, который, если вы введете неправильное слово, например `engino`, будет нарезать слово посимвольно (`e-n-g-i-n-o` -> `e-n-g-i-n` -> `engine`), чтобы автоматически определить наиболее вероятное слово в официальном словаре.
3.  **Умная обработка потерянных слов:** Если алгоритм находит неизвестное слово без совпадения префикса в словаре, он автоматически преобразует его в подстановочный знак (`*`), чтобы протестировать все возможности словаря по очереди в автоматическом режиме.
4.  **Ранняя обрезка ветвей (Early Branch Pruning):** Я разработал поисковый движок с ранней обрезкой на основе ограничений (обязательные слова и исключенные слова - NOK), что не позволяет процессору вычислять миллиарды бесполезных перестановок.
5.  **Встроенный обход контрольной суммы:** Поскольку фразы BIP-39 содержат контрольную сумму, код отбрасывает **99.6%** всех сгенерированных комбинаций еще до попытки выполнить сложные расчеты эллиптических кривых, экономя время процессора в 1000 раз.

## 🛠️ Возможности восстановления и поисковая инженерия

Изначально разработанный в **2023** году как эксклюзивный внутренний инструмент для экосистемы **b2 wallet** ([better2better](https://better2better.net)), **cryptoseed** был открыт для публичного доступа, чтобы предоставить инфраструктуру восстановления, научно превосходящую обычные рыночные решения. Поисковый движок обладает следующими возможностями и технологическими отличиями:

### 🎯 Маркировка состояния каждого слова
В отличие от тривиальных скрипстов восстановления, интерактивный мастер позволяет вам настроить уровень доверия для каждого слова в сид-фразе индивидуально, используя три семантических класса:
* **✔️**: Слово и его точное положение в сид-фразе подтверждены. Движок фиксирует это слово и перенаправляет вычислительную мощность исключительно на оставшиеся позиции.
* **🔀**: Слово известно и принадлежит набору, но его положение неверно или неточно. Движок динамически учитывает это слово для безопасных перестановок только на свободных позициях, избегая дублирования тестов.
* **🎲**: Слово полностью потеряно или нечитаемо. Движок в автоматическом режиме полностью тестирует все возможные варианты из словаря соответствующего формата.

### 📊 Предварительная обработка и оценка осуществимости
Прежде чем расходовать вычислительную энергию, движок анализирует сид-фразу и предоставленные ограничения, чтобы отобразить подробную математическую сводку:
* **Сырое поисковое пространство**: Показывает точное математическое количество теоретических комбинаций, которыми обладает текущая конфигурация.
* **Обрезка дерева (контрольная сумма и фильтры)**: Сообщает, сколько комбинаций остается после применения быстрых логических фильтров (таких как контрольные суммы или ограничения на слова NOK), что резко снижает объем сложных дериваций ключей.
* **Проекция времени сканирования**: Сравнивает в реальном времени оценку времени сканирования при использовании соединений со средней задержкой (публичные API) и высокопроизводительных локальных соединений (локальная RPC-нода).
* **Предупреждение о невыполнимости**: Движок прозрачно предупреждает пользователя, если настроенная сложность требует мощностей суперкомпьютера, предотвращая ненужное зависание оборудования пользователя.

### 🌐 Множество движков валидации и форматов
Экосистема поддерживает различные криптографические структуры с правилами валидации, специфичными для каждого формата:
* **Движок BIP-39**: Поддерживает фразы из **12, 15, 18, 21 и 24 слов**, применяя встроенную проверку контрольной суммы (*checksum*) для отсеивания **99.6%** неверных гипотез перед деривацией.
* **Движок Electrum**: Валидация и деривация на основе уникальных правил сид-фраз Electrum (Legacy и Modern).
* **Движок Electron Cash**: Точная адаптация логики деривации и проверки контрольных сумм экосистемы Bitcoin Cash.
* **Режим без валидации (брутфорс)**: Чистый генератор деривации без проверки контрольной суммы; идеально подходит для проприетарных устаревших форматов или нестандартных пользовательских сид-фраз, гарантируя максимальный охват поиска.

### 🧩 Решение сложных комбинированных сценариев
Движок решает задачи высокой сложности за один запуск, включая:
* Одно или несколько слов, полностью утерянных на известных или неизвестных позициях.
* Известные слова, порядок которых перепутан.
* Смешанные сценарии (например: когда слова отсутствуют и одновременно известные слова находятся не на своих местах).
* Выбор профиля поиска: **Максимальная скорость** (с использованием контрольных сумм и ограничений) или **Максимальный охват** (широкий математический брутфорс).

## 🛡️ Как использовать в вашем коде (API JavaScript)

Библиотека предоставляет чистый и хорошо структурированный экспорт для немедленной интеграции логики безопасности **b2 wallet** в ваше приложение:

```javascript
const { wordlists, searchEngine, addressDeriver, typo } = require('cryptoseed');

// 1. Исправление опечатки с помощью технологии «нарезки букв»
const dictionary = wordlists.bip39.ru || wordlists.bip39.en;
const wordWithError = "*";
const suggestions = typo.getPrefixSuggestions(wordWithError, dictionary);
console.log("Угаданное слово:", suggestions); // Возвращает [ 'engine' ]

// 2. Получение реального публичного адреса для MetaMask (EVM)
const seed = "cabin engine harvest fiction witness walnut ladder tumble insect fox notable spoon";
const ethAddress = addressDeriver.deriveAddress(seed, 'metamask', 'ETH', 0);
console.log("Ethereum-адрес:", ethAddress);

// 3. Получение кастомного адреса с использованием криптографии B2 Wallet
const b2Address = addressDeriver.deriveAddress(seed, 'b2wallet', 'BTC', 0);
console.log("Bitcoin-адрес в B2 Wallet:", b2Address);
```

    cryptoseed --help

    ```bash
    cryptoseed --info
    ```

## 🛠️ Производительность: Локальная RPC-нода против публичного API

В конце каждого поиска **cryptoseed** сохраняет подробный отчет о восстановлении на ваш диск (`resultado_recuperacao_[timestamp].txt`) и предоставляет реальную оценку скорости запросов для проверки наличия балансов в сети:

*   **Запросы через публичные API (50 мс на запрос):** Полезно только в том случае, если у вас очень мало фраз-кандидатов ($<100$). Замедляется из-за задержки в интернете и лимитов на запросы.
*   **Запросы через локальную RPC-ноду (0.1 мс на запрос):** Идеальный путь для объемных поисков ($>1000$ фраз). Сокращает общее время сканирования в **500 раз** за счет выполнения на локальной машине.

Оригинальный клиент Сатоши Накамото (Bitcoin-Qt) генерировал случайные закрытые ключи и сохранял их непосредственно в бинарный файл `wallet.dat`. Если вы утеряли этот файл, никакая фраза из слов не сможет восстановить ваши средства, поскольку детерминированные фразы просто еще не были изобретены!
